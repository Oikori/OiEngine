# 幸存者（Survivors/）

> 返回 [AGENTS.md](../AGENTS.md)。相关：[平台跳跃](平台跳跃.md)（输入屏蔽约定）、[ImGui 与输入](ImGui与输入.md)（IME 吞键）。

独立可执行工程（根 `CMakeLists.txt` 里的 `add_subdirectory(Survivors)`），不依赖 SandBox；只链接 `Engine`。

- **玩法**：WASD 移动 + 武器自动索敌；击杀敌人**当场获得经验**，掉落物是**金币**；
  **开局选一个角色 + 一把武器**，每次升级从三张**属性卡**里选一项（可花金币整组刷新），
  **每 5 级**从四把武器里选一把（新武器或已有武器 +1 级），**每关通关后开商店**买道具（可整组刷新）。
  **关卡制，共 10 关**，撑完第 10 关即胜利。四把武器 + 九种属性卡（无层数上限，带品质）+ 25 种道具，
  卡池在 `BuildUpgradePool()`、道具目录在 `SurvivorsItems.cpp` 的 `ITEM_DEFS`
- **开局选择**（`State::Setup`）：`ResetRun()` 清局后直接停在选角界面，`RenderSetup()` 给四张角色卡 + 四张武器卡，
  两者都有默认选中，点底部的「开始战斗」（或 Enter）进 `BeginRun()`；底部这一行会钳在屏幕内，窗口再矮也点得到。角色是**角色类道具**（品质固定史诗），只给初始属性；
  武器开局只带一把 1 级的（`m_weaponLevel` 其余全 0），其余靠每 5 级的选择解锁
- **武器选择**（`State::WeaponPick`）：`GainExp()` 里每升到 5 的倍数 `++m_pendingWeaponPicks`，
  面板列出四把武器的当前等级与下一级数值（`DescribeWeapon()`），满级 5 级的置灰；
  **全部武器满级**时这次机会直接在 `StartWeaponPick()` 里折成金币（`WEAPON_PICK_FALLBACK_COINS`），不弹面板。
  **雷暴是范围伤害**：每道雷随机挑一个敌人作落点，以落点为圆心按 `STORM.radius[level]`
  （90 / 100 / 112 / 126 / 145）结算半径内所有敌人，逐只掷暴击；`STORM.damage[]` 已按 AoE 下调
- **道具**：`ItemId` + `ITEM_DEFS`（名字 / 种类 / 固定稀有度 / 持有上限 / 配色）是唯一目录，**种类决定能不能重复拿**：
  普通类无持有上限、限制类每件上限 2~3（`ItemCap`）、独特类**全局只能持有一件**（`UniqueHeld() > 0` 就不再出）、
  角色类只在开局选。**稀有度是每件道具写死的档位**（同一件道具永远同一个稀有度，不会有「铁片-普通 / 铁片-高级」），
  只用于展示色、价格与出货权重——效果就是 `ItemGainFor()` 里那组固定数，不再乘稀有度倍率。
  道具效果在 `ApplyItemEffect()` 里**立即结算**：属性类直接写进 `BaseStats`，行为类落成标志位
  （`reviveCharges` 不朽之心 / `thornRatio` 荆棘之甲 / `coinGainMul` 贪婪之匣），
  事件类则把数值写进 `BaseStats` 的 `killHeal` / `killBurstDamage` / `coinHeal` / `hurtBurstDamage` 等字段，
  真正的效果只在对应事件发生时读（见下面「事件」），背包只记件数。
  **改 `ItemId` 顺序必须同步 `ITEM_DEFS`**（下标就是 ItemId，错位会让名字和效果对不上）
- **事件**（`SurvivorsEvents.cpp`）：四类「事件」在发生处各发一次 `RaiseEvent()`——
  `KillEnemy()` 发 `EventId::Kill`、`UpdateCoins()` 拾取时发 `CoinPickup`（金额 = 实际到手面额）、
  `DamagePlayer()` 发 `Hurt`、`AdvanceStage()` 发 `StageClear`。**道具对事件的响应全集中在 `RaiseEvent()` 的 switch 里**：
  新增一种事件 = `EventId` 加一项 + 在发生处发一次 + 在 switch 里写响应；阈值类道具（每 N 次触发）的数值照常写进
  `BaseStats`（`ApplyItemEffect()`），触发节奏在 `SurvivorsInternal.h`（`KILL/COIN/HURT_EVENT_STEP`）。
  七件事件道具：噬魂匕（每次击杀回血）/ 哀嚎钟（每 12 杀音波）/ 铸币者之锤（每 10 枚金币额外铸币）/
  拾荒护符（每 10 枚金币回血）/ 贪欲之链（每次拾币按面额震伤四周）/ 受难者圣痕（每 5 次受伤暗焰反击）/
  黎明誓约（每次过关永久 +伤害 / +生命上限并回血）。触发进度**只在持有关联道具时累积**（买之前的事件不白攒），
  暂停面板的「事件」一栏显示四类事件的累计次数与 `N / 阈值` 进度。事件会互相引发（音波 → 击杀 → 又一次击杀事件），
  所以 `RaiseEvent` 带递归深度上限 `MAX_EVENT_CHAIN`：超过后只记账、不再引爆新的范围伤害
- **商店**（`State::Shop`）：`AdvanceStage()` 置 `m_shopPending`，排队处理完升级 / 选武器后由 `OpenShop()` 打开；
  一次 4 个货位（`SHOP_SLOT_COUNT`），候选池是「所有未到持有上限的非角色道具」，
  出货权重按道具的固定稀有度（普通 6 / 高级 3 / 稀有 1.5 / 史诗 0.6，所以独特道具最稀）；
  价格按稀有度（12 / 22 / 40 / 66）再乘关卡系数（+10%/关，与金币掉落同步）；整组刷新（**快捷键 R**）价 = 6 + 4 × 本次已刷新次数，
  会尽量避开刚摆出来的那几件。**角色不进商店**（`CanAcquireItem()` 对角色类直接返回 false）
- **面板排队**：一次击杀可能连升两级、过关时可能还挂着升级——`ContinueRun()` 统一按
  **升级 → 选武器 → 商店** 的顺序推进，全部处理完才回到 `State::Playing`（`UpdateGame()` 结尾也走同一套判断）
- **经验与金币**：`KillEnemy()` 里 `GainExp(enemy.xp)` 直接结算经验，同时 `SpawnCoin()` 撒下金币（面额见 `ENEMY_TUNING` 的 `coins`，
  按关卡 +10%/关；石魔拆两枚、使徒拆十二枚）。金币用于**刷新升级卡 / 刷新商店 / 买道具**，拾取时飘出金色 `+N`；
  掉落物 22 秒（`COIN_LIFETIME`）后过期散掉，掉落表满（`MAX_COINS`）时最老的一枚直接折成钱，不会静默丢失。
  实际到手数额统一走 `CoinGain()`（贪婪之匣的金币倍率），否则拾取提示会和钱包对不上
- **刷新升级卡**：面板下方一个「刷新全部三张」按钮（**快捷键 R**），**整组重抽**（三张一起换，且尽量不重复刚才那三张），不消耗升级次数。
  价格 `RerollCost()` = `4 + 3 × 本次选取已刷新次数`，次数在每次开面板时清零（`StartLevelUp()` / `ContinueRun()`）；
  金币不足时按钮置灰并显示「需 N 币」，此时按 R 也只会响一声「不行」
- **升级卡池只剩属性卡**：武器卡与「血之祭」立即回复卡已从卡池移除（武器走每 5 级的选择，回复改由商店的血袋等道具提供），
  `UpgradeOption` 因此只剩下被动下标 + 品质两个字段
- **属性卡品质**（只作用于升级卡，道具不参与）：`普通 / 高级 / 稀有 / 史诗`，加成倍率 **1.0 / 1.6 / 2.4 / 3.5**，
  抽卡权重随等级倾斜（`RollRarity(int depth)`：普通 58−1.4×depth 起，史诗 4+0.55×depth；传当前等级）。
  **卡片只显示品质名**（分色标签），不显示加成倍率
- **属性卡无上限**：同一张卡可以一直叠（层数记在 `m_passive` 里，**卡片上不显示层数**，标题就是被动名）。
  为防堆叠打崩玩法只留两条硬上限：
  移速 ≤ 2× 裸值、暴击率 ≤ 100%（`MOVE_SPEED_CAP_MUL` / `CRIT_CHANCE_CAP`）
- **关卡**：第 `n` 关存活 `30 + 5 * (n - 1)` 秒（第 1 关 30 秒，第 10 关 75 秒，全通约 525 秒）；
  **只有第 5 / 10 关有「血月使徒」**，进关时直接从玩家周围 560 单位处刷新。过关由 `AdvanceStage()` 处理：
  清空剩余敌人与弹丸、地上金币自动收进钱包、重置刷怪计时、置 `m_shopPending`，并触发 2.2 秒进关横幅
  （Boss 关显示血色横幅 + 一层血光；横幅会被商店标题压住，所以 `OpenShop()` 会把它清零）。
  怪物数值按关卡递增（`SpawnEnemy()`）：血量 +30%/关、伤害 +12%/关、防御 +8%/关、经验与金币 +10%/关；
  刷怪间隔与同屏波数也随关卡收紧，兵种逐关放开（第 2 关起有食尸鬼、第 4 关起怨灵、第 7 关起石魔）
- **入口**：启动先进 `State::Title`（标题面板：开始游戏 / 游戏说明 / 设置 / 退出游戏）。
  **标题页没有键盘快捷键**：`OnEvent` 在 `State::Title` 直接返回、`RenderTitle` 也不再看 ImGui 的 Enter/空格，
  「开始游戏」只能点按钮（避免误按空格直接开局）。点「开始游戏」→ `ResetRun()` → `State::Setup` 选角色 + 武器
  → `BeginRun()` 开打；`OnAttach` 里 `ResetRun()` 后切 Title 并清掉开局敌人，标题画面不跑游戏逻辑、也不显示 HUD
- **帮助面板**：标题页与暂停菜单里都有「游戏说明 / 操作」按钮，`m_showHelp` 驱动 `RenderHelp()`（最后绘制，永远在最上层），
  内容是关卡规则 / 开局 / 操作 / 成长 / 道具 / 属性与品质 / 敌人七段；ESC 或面板内的关闭按钮收起。
  帮助打开时输入被接管：ESC 只关帮助，不会顺手开始游戏、暂停或重开（`PollPauseKeys()` 里把
  「关面板」放在「暂停 / 回标题」之前，`OnEvent` 在面板打开时直接返回）
- **属性**：`BaseStats` 是一局内唯一的属性数据（开局为裸值 `BARE_STATS`，初始生命 20），属性卡与道具**直接累加**到对应字段，
  战斗、升级卡描述、暂停面板都只读它；`RecalculateStats()` 只做「同步生命上限 + 钳制当前血量」，不做任何乘算。
  单张卡的步长 = 基准 × 品质倍率（`PassiveGainFor()`，描述与结算共用同一份算式）。基准值已整体砍到最初的三成左右：
  力量 3% / 急速 2.5% / 疾行 1.67% 裸移速（≈ +4）/ 体魄 2 / 磁石 8.3% 裸拾取（≈ +18）/ 幸运 1.5% / 回春 1（单独 ×10） / 铁壁 2 / 破甲 1 点固定穿甲；
  百分比型成长（移速 / 拾取）按开局裸值取比例，叠加是线性加成而非复利。
  道具额外带来四个维度：`critDamageMul`（暴击伤害倍率）/ `coinGainMul` / `thornRatio`（荆棘反弹）/ `reviveCharges`（不朽之心复活次数）
- **防御 / 穿甲**：**防御与穿甲都只有固定值**。减伤率 = `防御 / (防御 + 100)`（100 点 = 50%，只会趋近 100%，
  所以没有减伤保底）；穿甲直接扣对方的防御点数（扣到 0 为止，溢出部分不额外生效），剩下的防御再按上式换减伤率。
  结算统一走 `ResolveDamage(raw, penFlat, defense)`（攻防两端共用），等价写法：
  `raw * 100 / (100 + max(0, 防御 - 穿甲))`。**「破甲」只给固定穿甲**——早先那档「百分比穿甲」已随这次调整删掉
  （`BaseStats::penPercent` 与双档结算一并移除）。
  玩家靠「铁壁」/「破甲」属性卡与铁片 / 龙鳞 / 磨刀石等道具成长；**怪物只有防御、没有穿甲**
  （`ENEMY_TUNING` 的 `defense`：蝙蝠 0 / 食尸鬼 5 / 怨灵 12 / 石魔 25 / 使徒 40），
  所以玩家的防御在挨打时全额生效，玩家的穿甲直接抵消怪物防御
- **音频**：`Survivors/assets/audio/`（`Survivors/tools/generate_audio.py` 程序化生成）——
  2 首 BGM（主曲 / Boss 曲，streaming 循环，标题页起主曲、进 Boss 关切曲、过关切回）+ 11 个音效。
  `EnsureBgm(boss)` 管 BGM 生命周期（同一首只 Resume，换曲才停旧起新），`PlaySfx(SfxId, ...)` 按槽位冷却（45~120 ms）
  并按事件变调，避免命中 / 拾取连成一片；阵亡与通关会停 BGM 再播长音效。详见 [音频](音频.md)
- **音量 / 设置**：三级音量——主音量走 `AudioEngine::SetMasterVolume`，背景音乐与音效是应用层系数
  （引擎没有音频总线）：BGM 在 `EnsureBgm` / `ApplyBgmVolume` 里乘进场声部音量，音效在 `PlaySfx` 里乘进每次播放。
  标题页与暂停菜单都有「设置 / 音量」按钮打开 `RenderOptions()`（三条滑条 + 静音，ESC 关闭），
  设置只在本次运行内有效，不落盘
- **输入**：移动用 `Input::IsKeyPressed` 轮询；**所有关键操作都有鼠标路径**——升级卡、武器卡、商店购买、
  角色 / 武器选择都是大按钮，右上角另有「暂停」按钮（ESC 之外的鼠标路径），键盘 `1/2/3(/4)` 与 `R` 只是额外通道。
  中文输入法不会吞按键：引擎解绑了窗口的 IME，并有物理按键（GetAsyncKeyState）兜底（见 [ImGui 与输入](ImGui与输入.md) 的「输入法」一节）
- **暂停菜单**：继续游戏 / **回到标题** / 游戏说明 / 设置 / 退出游戏。
  「回到标题」走 `ReturnToTitle()`（清局 + 切 `State::Title`），**不**就地重开——想换角色 / 武器就回标题重新开始；
  另外 `R` 是**同一个键两种语义**（见下一条）：游戏内重开一局（直接进选角界面，暂停状态同样有效），
  **升级面板 / 商店里则是「整组刷新」**。暂停 / 继续只认 ESC（`P` 键已取消）
- **R**：和 ESC 一样由 `PollHotkeys()` 在 `OnUpdate` 里**每帧物理轮询** + 边沿检测，按状态分派：
  `LevelUp` → `RerollOptions()`、`Shop` → `RerollShop()`（与面板按钮同一条路径，金币不足同样不生效）、
  `Playing / Paused / GameOver / Victory` → `ResetRun()` 重开一局；标题 / 选角 / 选武器不响应。
  同样不能走事件通道：点过面板按钮后 ImGui 会吃掉键盘事件
- **ESC**：这个键由 `PollPauseKeys()` 在 `OnUpdate` 里**每帧轮询** `Input::IsKeyPressed`
  （物理按键状态，带 `GLFW_FOCUSED` 判断），自己做边沿检测（按住只算一次），
  然后按状态分派：打开 / 关闭暂停菜单、收起帮助 / 设置面板、选角页回标题、商店里离开商店。
  为什么不用事件：ImGui 窗口（暂停菜单、F4 调试面板、升级卡……）拿到焦点时，`ImGuiLayer` 会把键盘事件
  标成 handled，ESC 根本进不到游戏层（「点过调试面板之后 ESC 就不灵了」）；轮询不受 ImGui 影响，
  但窗口整体失焦时仍然不响应（玩家切到别的程序时按键不该影响游戏）。
  **事件通道（`OnEvent`）与 ImGui 都不再处理 ESC / R**——多处处理会让同一次按键互相抵消。
  所以暂停**不需要** `m_pauseGuardTime` 那种时间宽限（一次物理按下 = 一次切换），那个成员已删除。
  HUD 上的「暂停」按钮窗口必须带 `NoFocusOnAppearing | NoNavFocus`：否则它一出现就被 ImGui 聚焦，
  `io.WantCaptureKeyboard` 常真，整个游戏期间的键盘事件（F4 / R）都会被吞掉
  （F4 面板里有一行「ImGui 键盘捕获 / 导航」可以现场看这个状态）
- **结算窗口**：阵亡与通关面板都提供「再来一局 (R) / 回到标题 / 退出游戏」，并展示击杀 / 等级 / 获得金币 / 伤害。
  `ReturnToTitle()` = `ResetRun()`（重置关卡、属性、道具、金币、音频）后切 `State::Title`，
  再清空敌人 / 弹丸 / 金币 / 粒子 / 伤害数字 / 空间哈希，所以标题画面不会有残留敌人，下一局也一定从第 1 关开始
- **敌人管理**：敌人数量上限 420；用 `EnemyGrid`（96 单位空间哈希）做分离 / 索敌 / 弹丸碰撞 / 光环与荆棘查询；
  敌人离玩家超过 1400 单位会从视野外重新入场（Boss 单独按 1100 单位处理），否则玩家直线逃跑会让屏幕空掉
- **渲染**：全部程序化顶点色网格（`SurvivorsArt`），单 shader（`u_Transform` / `u_Tint` / `u_Falloff`）；
  正交相机跟随，900 高度基准 1:1。玩家形象按开局选的**角色**切换（`SurvivorsArt::playerWatchman/Hunter/Sister/Warlock`：重甲盾锤 / 兜帽长弓 / 头巾十字杖 / 尖帽法球），法阵与身周微光再取**角色配色**（`ItemColor(m_character)`），剪影 + 配色一起区分四个人。
  深度测试是 `GL_LESS`，**屏幕暗角（径向渐变网格）必须最后画**，否则它会写入深度、把 z 更小的全屏闪光裁成一个椭圆。
  HUD 只保留左上「生命 / 等级 / 金币 / 角色 + 道具件数」、顶部中央「关卡计时 + 击杀」、右上「暂停」，
  以及按需出现的 Boss 血条与进关横幅；暂停面板里查看「当前属性 / 武器 / 角色 / 道具」，
  **祝福（属性卡）清单不再列出**——它的效果已经全部反映在「当前属性」那几张数值上
- **每帧**显式 `Renderer::SetHDREnabled(false)` / `SetLightCullingEnabled(false)`，与 SandBox 各场景同样的约定
- 调试：F4 面板（额外有「升一级 / +50 金币 / 立刻过关 / 送事件道具」四个快速验证按钮）；
  `output/Survivors.exe` 直接运行同样需要 MinGW 运行时 DLL 在 PATH 中

## 代码分工

游戏层只有一个类 `SurvivorsLayer`，但按职责拆成多个 `.cpp`（都只定义它的成员函数，共享 `SurvivorsGame.h`；
新增 `.cpp` 要同时加进 `Survivors/CMakeLists.txt`）：

| 文件 | 职责 |
|---|---|
| `SurvivorsGame.cpp` | 主循环与生命周期：`BaseStats` 定义、相机、清局 / 回标题、音频、关卡推进、玩家移动、输入事件 |
| `SurvivorsEnemies.cpp` | `EnemyGrid` 空间哈希、刷怪节奏、敌人移动与分离、接触伤害、Boss 登场 |
| `SurvivorsWeapons.cpp` | 索敌 + 四把武器的开火 / 冷却（`UpdateWeapons`）与弹丸推进（`UpdateProjectiles`） |
| `SurvivorsCombat.cpp` | `DamageEnemy` / `KillEnemy` / `DamagePlayer`（含荆棘反弹与不朽之心复活）、金币掉落与拾取、粒子 / 光环 / 伤害数字及更新；击杀与拾取金币的**事件**在这里发出 |
| `SurvivorsUpgrade.cpp` | `GainExp`（含每 5 级排武器选择）、卡池与品质（`BuildUpgradePool` / `RollOption`）、整组刷新、`ApplyUpgrade` |
| `SurvivorsItems.cpp` | 道具目录 / 持有上限 / 效果结算、商店（掷货 / 刷新 / 购买）、开局选角与每 5 级选武器、面板排队 `ContinueRun` |
| `SurvivorsEvents.cpp` | 事件分发 `RaiseEvent`（击杀 / 拾取金币 / 受伤 / 过关）、事件道具的响应与范围爆发、暂停面板的 `EventSummary` |
| `SurvivorsRender.cpp` | `RenderWorld` 与全部 `Draw*`（程序化网格绘制顺序） |
| `SurvivorsUi.cpp` | `OnImGuiRender` 与全部面板（标题 / 选角 / HUD / 升级卡 / 选武器 / 商店 / 暂停 / 阵亡 / 通关 / 帮助 / 设置） |
| `SurvivorsInternal.h` | **内部**共享：尺寸与节奏常量、调色板、武器 / 敌人数值表、品质与道具种类表、`ResolveDamage` 等 `inline` 工具 |

`SurvivorsInternal.h` 里的东西全部是 `inline` / `inline constexpr`（拆文件后需要跨翻译单元共用同一份定义），
只在 Survivors 目标内部 include；改数值只动这一个文件，逻辑各回各文件。
道具目录（`ITEM_DEFS`）是唯一例外：它需要 `SurvivorsLayer` 的私有枚举，所以做成类的 `static const` 成员，定义放在 `SurvivorsItems.cpp`。
