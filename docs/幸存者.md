# 幸存者（Survivors/）

> 返回 [AGENTS.md](../AGENTS.md)。相关：[平台跳跃](平台跳跃.md)（输入屏蔽约定）、[ImGui 与输入](ImGui与输入.md)（IME 吞键）。

独立可执行工程（根 `CMakeLists.txt` 里的 `add_subdirectory(Survivors)`），不依赖 SandBox；只链接 `Engine`。

- **玩法**：WASD 移动 + 武器自动索敌；击杀敌人**当场获得经验**，掉落物是**金币**；
  **开局选一个角色 + 一把武器**，每次升级从三张**属性卡**里选一项（可花金币整组刷新），
  **每 5 级**从四把武器里选一把（新武器或已有武器 +1 级），**每关通关后开商店**买道具（可整组刷新）。
  **关卡制，共 10 关**，撑完第 10 关即胜利。四把武器 + 九种属性卡（无层数上限，带品质）+ 44 种道具，
  卡池在 `BuildUpgradePool()`、道具目录在 `SurvivorsItems.cpp` 的 `ITEM_DEFS`
- **开局选择**（`State::Setup`）：`ResetRun()` 清局后直接停在选角界面，`RenderSetup()` 给四张角色卡 + 四张武器卡，
  两者都有默认选中，点底部的「开始战斗」（或 Enter）进 `BeginRun()`；底部这一行会钳在屏幕内，窗口再矮也点得到。角色是**角色类道具**（品质固定史诗），给初始属性 + 一条专属特性（见下「角色特性」）；
  武器开局只带一把 1 级的（`m_weaponLevel` 其余全 0），其余靠每 5 级的选择解锁
- **武器选择**（`State::WeaponPick`）：`GainExp()` 里每升到 5 的倍数 `++m_pendingWeaponPicks`，
  面板列出四把武器的当前等级与下一级数值（`DescribeWeapon()`），满级 5 级的置灰；
  **全部武器满级**时这次机会直接在 `StartWeaponPick()` 里折成金币（`WEAPON_PICK_FALLBACK_COINS`），不弹面板。
  **雷暴默认是单体**：每道雷挑一个敌人，只结算落点那一只（**第一道必打最近的敌人、第二道优先打 Boss**（血月使徒，没有 Boss 就退回随机），其余随机），逐道掷暴击；
  **术士的雷暴是范围伤害**：以落点为圆心按 `STORM.radius[level]`（90 / 100 / 112 / 126 / 145）结算半径内所有敌人。
  攻击间隔 = `STORM.cooldown[level]`（术士再 -0.75 秒，见 `StormInterval()`，下限 `STORM_MIN_COOLDOWN`）
- **角色特性**（四个角色各一条，数值常量在 `SurvivorsInternal.h` 的「角色特性」段，文案直接读这些常量）：
  - 守夜人：`DamageMul()` 里再乘 `1 + 0.01 × 防御`（每点防御 +1% 伤害）；生命 ≤50% 时 `DefenseStat()` 与
    `RegenPerSecond()` 都 ×2 ——「守夜」状态下防御翻倍会连带抬高这条伤害加成，越硬越疼
  - 猎手：`WeaponDamageMul()` 对月刃 / 回旋镰 ×1.4；月刃的穿透改成**弹射**：`UpdateProjectiles()` 里命中后
    从**弹丸当前位置**找最近的、不在 `hitIds` 里的敌人，把速度直接转过去（找不到就保持原方向，靠寿命结束），
    每次弹射顺带把寿命续到 `age + 0.5` 秒
  - 修女：圣光环 ×1.5；`DamagePlayer()` 每次受伤把 `m_characterGrace` 顶到 3 秒，这 3 秒里
    `AttackSpeedMul()` 与 `RegenPerSecond()` 都 ×2（`SISTER_GRACE_MUL`）；**移速不再参与**这条加成
  - 术士：开局 +40% 全部伤害（`ITEM_DEFS` 里 `CharWarlock` 的 `gain[0]`），雷暴改成范围伤害，
    `StormInterval()` 再砍 0.75 秒
- **道具**：`ItemId` + `ITEM_DEFS`（名字 / 种类 / 固定稀有度 / 持有上限 / `gain[5]` 数值）是唯一目录，**种类决定能不能重复拿**：
  普通类无持有上限、限制类每件上限 1~3（`ItemCap`；**原先的「独特类」已并入限制类**，每件上限 1，
  不再有「全局只能带一件」的限制）、角色类只在开局选。**稀有度是每件道具写死的档位**（同一件道具永远同一个稀有度，不会有「铁片-普通 / 铁片-高级」），
  只用于展示色、价格与出货权重——效果就是目录里 `gain[5]` 那组固定数（合在 `ItemDef` 里，不再有独立的 `ItemGainFor`），不再乘稀有度倍率。
  道具效果在 `ApplyItemEffect()` 里**立即结算**：属性类直接写进 `BaseStats`，行为类落成标志位
  （`reviveCharges` 不朽之心 / `thornRatio` 荆棘之甲 / `coinGainMul` 贪婪之匣），
  事件类则把数值写进 `BaseStats` 的 `killHeal` / `killBurstDamage` / `coinHeal` / `hurtBurstDamage` 等字段，
  真正的效果只在对应事件发生时读（见下面「事件」），背包只记件数。
  `ITEM_DEFS` 是 `unordered_map<ItemId, ItemDef>`，**键就是 ItemId**，不再依赖枚举顺序（漏登记会在 `.at()` 处直接抛异常）；
  条目里**不存颜色**——普通 / 限制道具按稀有度取 `RARITY_COLORS`，角色类取 `CHARACTER_COLORS`（选角卡 / HUD / 法阵共用）
- **事件**（`SurvivorsEvents.cpp`）：八类「事件」在发生处各发一次 `RaiseEvent()`——
  `KillEnemy()` 发 `Kill`、`UpdateCoins()` 拾取时发 `CoinPickup`（金额 = 实际到手面额）、
  `DamagePlayer()` 发 `Hurt`、`AdvanceStage()` 发 `StageClear`、
  `DamageEnemy()` 暴击时发 `CritHit`（在死亡判定之前）、`UpdateGame()` 每 `TICK_EVENT_SECONDS` 秒发 `Tick`、
  `BuyShopOffer()` / `RerollShop()` / `RerollOptions()` 扣钱后发 `SpendCoins`（金额 = 实际花费）、
  `GainExp()` 每升一级发 `LevelUp`。**道具对事件的响应全集中在 `RaiseEvent()` 的 switch 里**：
  新增一种事件 = `EventId` 加一项 + 在发生处发一次 + 在 switch 里写响应；阈值类道具（每 N 次触发）的数值照常写进
  `BaseStats`（`ApplyItemEffect()`），触发节奏在 `SurvivorsInternal.h`（`KILL/COIN/HURT/CRIT/SPEND_EVENT_STEP` 与
  `TICK_EVENT_SECONDS`）。
  十四件事件道具：击杀 —— 哀嚎钟（每 12 杀音波）/ 血契（每次击杀回血）；拾金 —— 铸币者之锤 / 拾荒护符 / 贪欲之链；
  受伤 —— 受难者圣痕（每 5 次受伤暗焰反击）；过关 —— 黎明誓约（每次过关永久成长）；
  暴击 —— 淬血匕首（每次暴击回血）/ 破晓之刃（每 8 次暴击光爆）；
  计时 —— 沙漏（每 8 秒回血）/ 节拍器（每 8 秒对最近敌人一击）；
  消费 —— 贪婪契约（每花 50 币回血）/ 商人之瞳（每花 50 币永久 +伤害）；
  升级 —— 成长之书（升级回血）/ 星辉残页（升级 +固定穿甲）。
  触发进度**只在持有关联道具时累积**（买之前的事件不白攒），
  暂停面板的「事件」一栏显示八类事件的累计次数与 `N / 阈值` 进度。事件会互相引发（音波 → 击杀 → 又一次击杀事件），
  所以 `RaiseEvent` 带递归深度上限 `MAX_EVENT_CHAIN`：超过后只记账、不再引爆新的范围伤害
- **商店**（`State::Shop`）：`AdvanceStage()` 置 `m_shopPending`，排队处理完升级 / 选武器后由 `OpenShop()` 打开；
  一次 4 个货位（`SHOP_SLOT_COUNT`），候选池是「所有未到持有上限的非角色道具」**且该稀有度已解锁**
  （`ShopSellsRarity()`：稀有档 `ITEM_RARE_UNLOCK_STAGE = 3`、史诗档 `ITEM_EPIC_UNLOCK_STAGE = 5`，
  按开商店时的 `m_stage` 判；第一次开商店是第 2 关，所以那时只卖普通 / 高级），
  出货权重按道具的固定稀有度（普通 6 / 高级 3 / 稀有 1.5 / 史诗 0.6，所以史诗档（原独特道具）最稀）；
  价格按稀有度（12 / 22 / 40 / 66）再乘关卡系数：**前 5 关每关 +20%（与原来的线性完全一致），第 6 关起叠加二次项**
  （`ShopPriceScale()`：`1 + 0.2·n + 0.4·max(0, n−5)²`，`n` = 已过关数；n=6~9 的系数是 2.6 / 4.0 / 6.2 / 9.2，
  每多过一关的增量 0.6 / 1.4 / 2.2 / 3.0，所以末两关已经很难买得起史诗档——第 10 关的史诗要 607 币）。
  金币掉落是固定值、不随关卡涨，所以越往后买东西越吃力；
  整组刷新（**快捷键 R**）价 = **(6 + 4 × 本次已刷新次数) × (1 + 0.4 × (n−1))**（`ShopRerollCost()`，`n` = 已过关数，
  第一次开商店系数正好 1.0，n<1 兜底钳到 1.0），
  刷新会尽量避开刚摆出来的那几件。**角色不进商店**（`CanAcquireItem()` 对角色类直接返回 false）。
  **离开商店只走底部的「离开商店」按钮**：Enter / 空格已取消（ESC 在商店里改为打开暂停面板，见下面「ESC」一条）
- **面板排队**：一次击杀可能连升两级、过关时可能还挂着升级——`ContinueRun()` 统一按
  **升级 → 选武器 → 商店** 的顺序推进，全部处理完才回到 `State::Playing`（`UpdateGame()` 结尾也走同一套判断）
- **经验与金币**：`KillEnemy()` 里 `GainExp(enemy.xp)` 直接结算经验，同时 `SpawnCoin()` 撒下金币（面额见 `ENEMY_TUNING` 的 `coins`：
  **小怪一律 1 枚、血月使徒 10 枚**，**固定基础值、不随关卡放大**；使徒拆成最多 12 枚（10 枚时就是 10 个 ×1），石魔面额 >1 时拆两枚）。金币用于**刷新升级卡 / 刷新商店 / 买道具**，拾取时飘出金色 `+N`；
  **金币不会过期**（没有 `COIN_LIFETIME` 了）：掉在地上就一直留着，走近自动吸走；
  `AdvanceStage()` / `TriggerVictory()` 会把**全地图**的金币一次性收进钱包。掉落表满（`MAX_COINS`）时最老的一枚直接折成钱，不会静默丢失。
  实际到手数额统一走 `CoinGain()`（贪婪之匣的金币倍率），否则拾取提示会和钱包对不上
- **刷新升级卡**：面板下方一个「刷新」按钮（**快捷键 R**），**三张一起重抽**（且尽量不重复刚才那三张），不消耗升级次数。
  价格 `RerollCost()` = `4 + 3 × 本次选取已刷新次数`，次数在每次开面板时清零（`StartLevelUp()` / `ContinueRun()`）；
  金币不足时按钮置灰并显示「需 N 币」，此时按 R 也只会响一声「不行」
- **升级卡池只剩属性卡**：武器卡与「血之祭」立即回复卡已从卡池移除（武器走每 5 级的选择，回复改由商店的血袋等道具提供），
  `UpgradeOption` 因此只剩下被动下标 + 品质两个字段
- **属性卡品质**（只作用于升级卡，道具不参与）：`普通 / 高级 / 稀有 / 史诗`，加成倍率 **1.0 / 1.6 / 2.4 / 3.5**，
  抽卡权重随等级倾斜（`RollRarity(int depth)`：普通 58−1.4×depth 起，史诗 4+0.55×depth；传当前等级）。
  **卡片只显示品质名**（分色标签），不显示加成倍率
- **属性卡无上限**：同一张卡可以一直叠（层数记在 `m_passive` 里，**卡片上不显示层数**，标题就是被动名）。
  只剩一条硬上限：暴击率 ≤ 100%（`CRIT_CHANCE_CAP`）；**移动速度不设上限**（疾行卡 / 追星靴 / 猎手角色都直接累加，
  `MoveSpeed()` 原样返回 `BaseStats.moveSpeed`），堆多少就跑多快
- **选卡后的无敌窗口**：`ApplyUpgrade()` 会把 `m_hurtCooldown` 顶到 `LEVELUP_INVULN_TIME`（1 秒），
  面板一关就贴脸的敌人打不到你（`UpdateContactDamage()` 在冷却 > 0 时整段跳过）；角色身上的红白闪烁就是这段无敌。
  连续升级时冷却不递减（面板里不跑 `UpdateGame`），所以实际无敌时间从真正回到战斗那一帧开始算
- **场地围栏**：玩家只能在以原点为中心、边长为 `2 × ARENA_HALF`（1100 → 2200 见方）的场地内移动——
  `UpdatePlayer()` 在移动之后用 `std::clamp` 钳住位置（留半个身位，速度不清零，贴边手感不受影响）。
  四条边上是程序化围栏：`CreateFencePost()`（立柱 + 尖头 + 一颗血色结界晶石）与 `CreateFenceRail()`（按段拉伸的横栏），
  每 `FENCE_SEGMENT`（260）一段、只画视野内的段。**敌人不拦**——否则怪会被关在栏杆外面，场地里反而空掉；
  栏杆上的血色晶石就是「只拦玩家」的视觉暗示。
  **围栏外是阴影区**：`DrawShadowZone()` 用四块矩形把场地外压暗（z 卡在墓碑之上、围栏之下，所以地面装饰被吞进阴影、
  栏杆本身保持清晰），围栏内侧再叠一条 **180 单位宽的渐变带**（`vignette` 网格旋转 90° 复用：满端贴栏杆、透明端朝场地内），
  阴影里的敌人整体压暗；`DamageEnemy()` 与武器索敌（`FindNearestEnemy()` / 雷暴落点候选）
  都先过 `InShadow()`——**阴影里的敌人无敌**，必须等它跨进场地才打得到
- **关卡**：第 `n` 关存活 `30 + 5 * (n - 1)` 秒（第 1 关 30 秒，第 10 关 75 秒，全通约 525 秒）；
  **只有第 5 / 10 关有「血月使徒」**，进关时直接从玩家周围 560 单位处刷新。
  **第 10 关的使徒是最终战：击杀它当场通关**（`KillEnemy` → `TriggerVictory()`），不必再撑完剩下的时间；
  第 5 关的使徒只是强敌（击杀回血 + 掉钱），不影响关卡计时。撑满 75 秒同样通关，计时只是保底，
  两条路径共用 `TriggerVictory()`（幂等：只结算一次，并顺手把地上没捡的金币收进钱包——瞬间通关时玩家来不及去捡）。
  过关由 `AdvanceStage()` 处理：
  清空剩余敌人与弹丸、地上金币自动收进钱包、重置刷怪计时、置 `m_shopPending`，并触发 2.2 秒进关横幅
  （Boss 关显示血色横幅 + 一层血光；横幅会被商店标题压住，所以 `OpenShop()` 会把它清零）。
  进关横幅与 HUD 在最终关会写明「击杀使徒即通关」，别让玩家以为还得硬撑倒计时。
  怪物数值按关卡递增（`SpawnEnemy()` 读 `EnemyHpScale / EnemyDefenseScale / EnemyDamageScale`，
  **Boss 的血量另走 `BossHpScale`**）：
  **小怪血量每关 +30%、防御每关 +20%（都是线性）**；**伤害是三次曲线** `1 + (n−1)³/81`
  （第 1/5/7/10 关 = 1.00 / 1.79 / 3.67 / 10.00 倍，末关约为初始值的 10 倍；第 5 关与旧二次曲线几乎重合，
  前期手感不变、最后三关才陡起来）；
  **血月使徒的血量单独一条分段曲线**：第 1~5 关线性 1 → 2 倍，第 5 关之后按公比 `20^(1/5) ≈ 1.8206` 放大，
  第 6/7/8/9/10 关 = 3.64 / 6.63 / 12.1 / 22.0 / 40.0 倍（第 5 关 2000、第 10 关 40000 血，
  即基础值 1000 的 2 倍 / 40 倍），**它的伤害与防御仍与小怪同一套**；
  **经验与金币固定为表里的基础值**（不随关卡放大，只靠刷怪量变多来增加总产出）；
  刷怪间隔与同屏波数也随关卡收紧，兵种逐关放开（第 2 关起有食尸鬼、第 4 关起怨灵、第 7 关起石魔）。
  `ENEMY_TUNING` 里是**生效基准值**（第 1 关血量 20 / 56 / 88 / 350 / 1000，使徒的 1000 是血量曲线的基准）
- **入口**：启动先进 `State::Title`（标题面板：开始游戏 / 游戏说明 / 设置 / 退出游戏）。
  **标题页没有键盘快捷键**：`OnEvent` 在 `State::Title` 直接返回、`RenderTitle` 也不再看 ImGui 的 Enter/空格，
  「开始游戏」只能点按钮（避免误按空格直接开局）。点「开始游戏」→ `ResetRun()` → `State::Setup` 选角色 + 武器
  → `BeginRun()` 开打；`OnAttach` 里 `ResetRun()` 后切 Title 并清掉开局敌人，标题画面不跑游戏逻辑、也不显示 HUD
- **帮助面板**：标题页与暂停菜单里都有「游戏说明 / 操作」按钮，`m_showHelp` 驱动 `RenderHelp()`（最后绘制，永远在最上层），
  内容是关卡规则 / 开局 / 操作 / 成长 / 道具 / 属性与品质 / 敌人七段；ESC 或面板内的关闭按钮收起。
  帮助打开时输入被接管：ESC 只关帮助，不会顺手开始游戏、暂停或重开（`PollPauseKeys()` 里把
  「关面板」放在「暂停 / 回标题」之前，`OnEvent` 在面板打开时直接返回）
- **属性**：`BaseStats` 是一局内唯一的属性数据（开局为裸值 `BARE_STATS`，初始生命 20），属性卡与道具**直接累加**到对应字段，
  战斗、升级卡描述、暂停面板都只读它；`RecalculateStats()` 只做「同步生命上限 + 钳制当前血量」，不做任何乘算。
  单张卡的步长 = 基准 × 品质倍率（`PassiveGainFor()`，描述与结算共用同一份算式）。基准值已整体砍到最初的三成左右：
  力量 3% / 急速 2.5% / 疾行 1.67% 裸移速（≈ +4）/ 体魄 2 / 暴击 1.5% / 爆伤 15% / 回春 1（单独 ×10） / 铁壁 2 / 破甲 1 点固定穿甲；
  百分比型成长（移速）按开局裸值取比例，叠加是线性加成而非复利；
  **拾取范围不再是属性卡**（原「磁石」卡已移除），只由「磁石」道具（原「引魂灯」）提供固定加成。
  道具额外带来四个维度：`critDamageMul`（暴击伤害倍率）/ `coinGainMul` / `thornRatio`（荆棘反弹）/ `reviveCharges`（不朽之心复活次数）
- **防御 / 穿甲**：**防御与穿甲都只有固定值**。减伤率 = `防御 / (防御 + 100)`（100 点 = 50%，只会趋近 100%，
  所以没有减伤保底）；穿甲直接扣对方的防御点数（扣到 0 为止，溢出部分不额外生效），剩下的防御再按上式换减伤率。
  结算统一走 `ResolveDamage(raw, penFlat, defense)`（攻防两端共用），等价写法：
  `raw * 100 / (100 + max(0, 防御 - 穿甲))`。**「破甲」只给固定穿甲**——早先那档「百分比穿甲」已随这次调整删掉
  （`BaseStats::penPercent` 与双档结算一并移除）。
  玩家靠「铁壁」/「破甲」属性卡与铁片 / 龙鳞 / 磨刀石等道具成长；**怪物只有防御、没有穿甲**
  （`ENEMY_TUNING` 的 `defense` 蝙蝠 0 / 食尸鬼 10 / 怨灵 24 / 石魔 50 / 使徒 100，第 1 关即 0% / 9.1% / 19.4% / 33.3% / 50.0% 减伤；
  再乘 `EnemyDefenseScale`（每关 +20%），第 10 关石魔 140、使徒 280 → 58.3% / 73.7% 减伤，靠「破甲」的固定穿甲往下扣），
  所以玩家的防御在挨打时全额生效，玩家的穿甲直接抵消怪物防御
- **音频**：`Survivors/assets/audio/`（`Survivors/tools/generate_audio.py` 程序化生成）——
  2 首 BGM（主曲 / Boss 曲，streaming 循环，标题页起主曲、进 Boss 关切曲、过关切回）+ 11 个音效。
  `EnsureBgm(boss)` 管 BGM 生命周期（同一首只 Resume，换曲才停旧起新），`PlaySfx(SfxId, ...)` 按槽位冷却（45~120 ms）
  并按事件变调，避免命中 / 拾取连成一片；阵亡与通关会停 BGM 再播长音效。详见 [音频](音频.md)
- **音量 / 设置**：三级音量——主音量走 `AudioEngine::SetMasterVolume`，背景音乐与音效是应用层系数
  （引擎没有音频总线）：BGM 在 `EnsureBgm` / `ApplyBgmVolume` 里乘进场声部音量，音效在 `PlaySfx` 里乘进每次播放。
  标题页与暂停菜单都有「设置 / 音量」按钮打开 `RenderOptions()`（三条滑条 + 静音，ESC 关闭），
  设置只在本次运行内有效，不落盘
- **输入**：移动用 `Input::IsKeyPressed` 轮询；**所有关键操作都有鼠标路径**——升级卡、武器卡、商店购买、
  角色 / 武器选择都是大按钮，右上角另有「暂停」按钮（ESC 之外的鼠标路径），键盘 `1/2/3(/4)` 与 `R` 只是额外通道。
  中文输入法不会吞按键：引擎解绑了窗口的 IME，并有物理按键（GetAsyncKeyState）兜底（见 [ImGui 与输入](ImGui与输入.md) 的「输入法」一节）
- **暂停菜单**：继续游戏 / **回到标题** / 游戏说明 / 设置 / 退出游戏。
  「回到标题」走 `ReturnToTitle()`（清局 + 切 `State::Title`），**不**就地重开——想换角色 / 武器就回标题重新开始。
  **从升级卡 / 商店暂停时，「继续游戏」回到那一屏**（`m_pauseReturnState`），不会把玩家直接丢回战斗。
  暂停 / 继续只认 ESC（`P` 键已取消）
- **R**：和 ESC 一样由 `PollHotkeys()` 在 `OnUpdate` 里**每帧物理轮询** + 边沿检测，**只在两个面板里有效**：
  `LevelUp` → `RerollOptions()`、`Shop` → `RerollShop()`（与面板按钮同一条路径，金币不足同样不生效）。
  其它状态（游戏内 / 暂停 / 阵亡 / 通关 / 选角）一律不响应——重开一局只能点结算面板的「再来一局」按钮，
  战斗中不会因为误触 R 把打了一半的一局直接清掉。
  同样不能走事件通道：点过面板按钮后 ImGui 会吃掉键盘事件
- **ESC**：这个键由 `PollPauseKeys()` 在 `OnUpdate` 里**每帧轮询** `Input::IsKeyPressed`
  （物理按键状态，带 `GLFW_FOCUSED` 判断），自己做边沿检测（按住只算一次），
  然后按状态分派：打开 / 关闭暂停菜单、收起帮助 / 设置面板、选角页回标题。
  **战斗、升级卡、商店三个阶段都能打开暂停**（`OpenPauseMenu()` 把当前状态记进 `m_pauseReturnState`，
  ESC 再按一次或暂停菜单的「继续游戏」回到那个状态——从商店 / 升级卡暂停的不会被打回战斗）。
  **商店的「离开商店」只留鼠标按钮**：Enter / 空格不再离开商店（`OnEvent` 的 `Shop` 分支直接 return，
  面板里的 `IsKeyPressed(ImGuiKey_Enter)` 判断也已删除），这样 ESC 在商店里才有空位去开暂停。
  为什么不用事件：ImGui 窗口（暂停菜单、F4 调试面板、升级卡……）拿到焦点时，`ImGuiLayer` 会把键盘事件
  标成 handled，ESC 根本进不到游戏层（「点过调试面板之后 ESC 就不灵了」）；轮询不受 ImGui 影响，
  但窗口整体失焦时仍然不响应（玩家切到别的程序时按键不该影响游戏）。
  **事件通道（`OnEvent`）与 ImGui 都不再处理 ESC / R**——多处处理会让同一次按键互相抵消。
  所以暂停**不需要** `m_pauseGuardTime` 那种时间宽限（一次物理按下 = 一次切换），那个成员已删除。
  HUD 上的「暂停」按钮窗口必须带 `NoFocusOnAppearing | NoNavFocus`：否则它一出现就被 ImGui 聚焦，
  `io.WantCaptureKeyboard` 常真，整个游戏期间的键盘事件（F4 / R）都会被吞掉
  （F4 面板里有一行「ImGui 键盘捕获 / 导航」可以现场看这个状态）
- **结算窗口**：阵亡与通关面板都提供「再来一局 / 回到标题 / 退出游戏」，并展示击杀 / 等级 / 获得金币 / 伤害。
  `ReturnToTitle()` = `ResetRun()`（重置关卡、属性、道具、金币、音频）后切 `State::Title`，
  再清空敌人 / 弹丸 / 金币 / 粒子 / 伤害数字 / 空间哈希，所以标题画面不会有残留敌人，下一局也一定从第 1 关开始
- **敌人管理**：敌人数量上限 420；用 `EnemyGrid`（96 单位空间哈希）做分离 / 索敌 / 弹丸碰撞 / 光环与荆棘查询；
  敌人离玩家超过 1400 单位会从视野外重新入场（Boss 单独按 1100 单位处理），否则玩家直线逃跑会让屏幕空掉
- **血月使徒的冲刺**（`SurvivorsEnemies.cpp` 的 `UpdateBossDash`）：使徒移速与玩家裸移速相同（**240**），
  压迫感来自技能——**靠近到 180~480 单位**且冷却（4.5 秒）结束时，先**锁定当时朝向玩家的方向**（`Enemy::dashDirection`），
  站定**蓄力 1 秒**，再沿这条直线以 1600 速度冲 **620** 单位（约 0.39 秒；撞到围栏会提前停在场地边缘，
  免得冲进阴影区变成无敌）。蓄力阶段不吃软推挤、不追踪玩家，横移就能躲开；冲刺阶段同样跳过分离 / 玩家推挤，
  轨迹是锁死的直线。触发有三个门槛：`BOSS_DASH_MIN_RANGE`（贴身时不冲，否则会在玩家身上原地站桩）/
  `BOSS_DASH_TRIGGER_RANGE` / `BOSS_DASH_COOLDOWN`，都在 `SurvivorsInternal.h`。
  收招时只留 25% 速度的惯性（常规转向按 5/s 收敛，全留着会再多滑出 ≈320 单位）。
  表现：蓄力时地面画出锁定的那条克制线（`vignette` 网格：满端朝冲刺方向、透明端贴使徒）+ 逐帧放大的血环、
  身体整体泛红；冲刺时身后拖一条 240 长的血色残影
- **渲染**：主体是程序化顶点色网格（`SurvivorsArt`），单 shader（`u_Transform` / `u_Tint` / `u_Falloff`）；
  正交相机跟随，900 高度基准 1:1。玩家形象按开局选的**角色**切换（`SurvivorsArt::playerWatchman/Hunter/Sister/Warlock`：重甲盾锤 / 兜帽长弓 / 头巾十字杖 / 尖帽法球），法阵与身周微光再取**角色配色**（`ItemColor(m_character)`），剪影 + 配色一起区分四个人。
  深度测试是 `GL_LESS`，**屏幕暗角（径向渐变网格）必须最后画**，否则它会写入深度、把 z 更小的全屏闪光裁成一个椭圆。
- **贴图素材（可选，优先于几何）**：`Survivors/assets/textures/` 下 9 张约定命名的 PNG（4 角色 + 5 敌人），
  当前风格是**暗黑哥特 Q 版（chibi 二头身）**，由 `Survivors/tools/prepare_sprites.py` 从生图产出的白底立绘切成透明精灵——四边 flood fill 去背景、
  按「白底混合」反解 alpha 与本色（顺手去掉抗锯齿留下的白边），最后等比裁进 512×512 画布居中，
  保证所有精灵的世界尺寸一致。`SurvivorsArt::Load()` 逐个槽位加载，**加载失败的槽位自动退回程序化剪影**
  （删掉整目录游戏照常能玩）。贴图走独立的 `survivors_sprite.glsl`（position + uv，采样器固定 unit 0）：
  `u_Tint` 管阴影压暗，`u_Flash` / `u_FlashColor` 把颜色往闪光色 mix（受击闪白 / Boss 蓄力泛红，
  几何那套「把 tint 提过 1.0」对贴图会糊）。`DrawEnemies` 先把贴图敌人收集进 `SpriteCommand`，
  循环外 `FlushSprites` 统一提交——几百个敌人也只切一次 program。开局选角卡片用 `playerSprite[i]`
  铺立绘（`ImGui::Image`），选人时先见到自己的形象。
  素材缺失时的行为：`Load` 日志会打印「角色 N/4 · 敌人 N/5」，一眼看出哪些槽位退回了几何。
- **图标（可选）**：`Survivors/assets/textures/icons/` 下 53 张 256×256 的 PNG——40 件道具（角色类道具没有独立图标，
  用立绘代替）+ 4 把武器 + 9 种被动（属性卡）。同一套切图脚本从生图的 4×4 / 2×2 图集切出来（`--size 256`），
  文件名按 `ItemId` / `WeaponId` / `PassiveId` 的**枚举顺序**登记在 `SurvivorsItems.cpp` 的 `LoadItemIcons()`
  里（三个 `static_assert` 卡住表长与枚举数对不上），缺文件的位置写 `nullptr` 就会自动跳过。
  UI 一律通过 `ItemIcon()` / `WeaponIcon()` / `PassiveIcon()` 取图，卡片用 `DrawCardIcon()` 在顶部居中画
  76px 图标（底下垫一层按稀有度取的淡光）；暂停面板的武器行与道具列表用 18px 小图标。
  `ImGui::Image` 的 UV 要**翻转 V**（`(0,1)-(1,0)`）——纹理是 stb_image 的 flip 约定，不翻会上下颠倒。
  HUD 只保留左上「生命 / 等级 / 金币 / 角色 + 道具件数」、顶部中央「关卡计时 + 击杀」、右上「暂停」，
  以及按需出现的 Boss 血条与进关横幅；暂停面板里查看「当前属性 / 武器 / 角色 / 道具」，
  **祝福（属性卡）清单不再列出**——它的效果已经全部反映在「当前属性」那几张数值上
- **每帧**显式 `Renderer::SetHDREnabled(false)` / `SetLightCullingEnabled(false)`，与 SandBox 各场景同样的约定
- 调试：F4 面板（额外有「升一级 / +50 金币 / 立刻过关 / 送事件道具」四个快速验证按钮）；
  `output/Survivors.exe` 直接运行同样需要 MinGW 运行时 DLL 在 PATH 中

## 代码分工

游戏层只有一个类 `SurvivorsLayer`，但按职责拆成多个 `.cpp`（都只定义它的成员函数，共享 `SurvivorsGame.h`；
新增 `.cpp` 要同时加进 `Survivors/CMakeLists.txt`）：

| 文件 | 职责 |
|---|---|
| `SurvivorsGame.cpp` | 主循环与生命周期：`BaseStats` 定义、相机、清局 / 回标题、音频、关卡推进、玩家移动、输入事件 |
| `SurvivorsEnemies.cpp` | `EnemyGrid` 空间哈希、刷怪节奏、敌人移动与分离、接触伤害、Boss 登场 |
| `SurvivorsWeapons.cpp` | 索敌 + 四把武器的开火 / 冷却（`UpdateWeapons`）与弹丸推进（`UpdateProjectiles`）；命中统一过 `Projectile::hitIds` 去重（**同一段飞行里对同一敌人只结算一次**；回旋镰抛出 → 收回换段时清表，所以同一目标去程回程各吃一次伤害）；回旋镰 `ThrowScythes` 是「一把锁最近敌人 + 其余按 360°/count 等分圆抛出」 |
| `SurvivorsCombat.cpp` | `DamageEnemy` / `KillEnemy` / `DamagePlayer`（含荆棘反弹与不朽之心复活）、金币掉落与拾取、粒子 / 光环 / 伤害数字及更新；击杀与拾取金币的**事件**在这里发出 |
| `SurvivorsUpgrade.cpp` | `GainExp`（含每 5 级排武器选择）、卡池与品质（`BuildUpgradePool` / `RollOption`）、整组刷新、`ApplyUpgrade` |
| `SurvivorsItems.cpp` | 道具目录 / 持有上限 / 效果结算、商店（掷货 / 刷新 / 购买）、开局选角与每 5 级选武器、面板排队 `ContinueRun` |
| `SurvivorsEvents.cpp` | 事件分发 `RaiseEvent`（击杀 / 拾取金币 / 受伤 / 过关 / 暴击 / 计时 / 消费 / 升级）、事件道具的响应与范围爆发、暂停面板的 `EventSummary` |
| `SurvivorsRender.cpp` | `RenderWorld` 与全部 `Draw*`（程序化网格 + 贴图精灵的绘制顺序） |
| `SurvivorsUi.cpp` | `OnImGuiRender` 与全部面板（标题 / 选角 / HUD / 升级卡 / 选武器 / 商店 / 暂停 / 阵亡 / 通关 / 帮助 / 设置） |
| `SurvivorsInternal.h` | **内部**共享：尺寸与节奏常量、调色板、武器 / 敌人数值表、品质与道具种类表、`ResolveDamage` 等 `inline` 工具 |

`SurvivorsInternal.h` 里的东西全部是 `inline` / `inline constexpr`（拆文件后需要跨翻译单元共用同一份定义），
只在 Survivors 目标内部 include；改数值只动这一个文件，逻辑各回各文件。
道具目录（`ITEM_DEFS`）是唯一例外：它需要 `SurvivorsLayer` 的私有枚举，所以做成类的 `static const` 成员，定义放在 `SurvivorsItems.cpp`。
