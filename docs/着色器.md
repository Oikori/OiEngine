# 着色器资源

> 返回 [AGENTS.md](../AGENTS.md)。相关：[渲染基础](渲染基础.md)、[光照与后处理](光照与后处理.md)。

所有 GLSL 都放在**各可执行工程自己的 `assets/shader/`** 下，C++ 源码里不再写 `R"(...)"` 着色器字符串。

## 目录组织

每个可执行工程都自带一份自己用到的全部着色器（自包含，可单独打包 / 单独分发）：

| 工程 | `assets/shader/engine/` | `assets/shader/scenes/` |
|---|---|---|
| `SandBox/` | tonemap、cluster 剔除 compute、探针 irradiance / prefilter | `plane_game`、`solar_system_*`（3）、`shadow_demo_*`（3）、`indoor_demo_*`（4）、`volumetric_cloud_*`（3） |
| `Platformer/` | 同上 4 个 | `platformer` |
| `Survivors/` | 同上 4 个 | `survivors` |

- `engine/` 下的 4 个属于引擎（`PostProcess` / `LightClustering` / `OpenGLEnvironmentProbe` 加载），但每个工程各存一份：
  **改引擎 GLSL 时三个工程的 `assets/shader/engine/` 要同步修改**，改完 diff 一遍确认一致
- `scenes/` 只放该工程自己的场景着色器；新增场景着色器丢进本工程目录即可，不需要改 CMake

## 构建

- 各工程 CMake 的 `POST_BUILD` 用 `copy_directory` 把整个 `assets/`（音频 + `shader/`）复制到 `output/assets/`；
  运行时按当前工作目录（`output/`）读取 `assets/shader/...`
- 三个工程的副本在 `output/assets/shader/engine/` 上内容相同，`copy_directory` 互相覆盖没有副作用

## 文件格式

一个文件可以包含多个阶段，用 `#type <stage>` 分段，`stage` 取 `vertex` / `fragment` / `compute`：

```glsl
#type vertex
#version 450 core
...

#type fragment
#version 450 core
...
```

- `#type` 行本身不会进入 GLSL；`#type` 之前的文本会被加载器丢弃，需要保留的说明写在 `#type` 之后（`#version` 之前允许注释）
- 只有 `#type compute` 的文件即计算着色器，可以直接 `Dispatch()`
- 命名按程序走：`<程序>.glsl`；计算着色器用 `<程序>.comp.glsl`（日志里的程序名由文件名推导）

## 加载

```cpp
// 文件路径加载（推荐）
m_shader = Shader::Create("assets/shader/scenes/indoor_demo_lit.glsl");
// compute
s_cullShader = Shader::Create("assets/shader/engine/light_cluster_cull.comp.glsl");

// 也可以用 ShaderLibrary 按名字登记
// engine.shaderLibrary.Load("IndoorLit", "assets/shader/scenes/indoor_demo_lit.glsl");
```

- `Shader::Create(filepath)` 走 `OpenGLShader(filepath)`：读文件 → `PreProcess` 按 `#type` 拆段 → 逐段编译 → 链接
- 内联版本 `Shader::Create(name, vertexSrc, fragmentSrc)` / `Shader::CreateCompute(name, src)` 仍保留，
  仅用于临时调试，新着色器请落文件
- 文件缺失时 `ReadFile` 会打印 `Could not open file '...'`，随后编译失败触发 `OI_ASSERT`；
  看到这条日志先确认是否在 `output/` 下启动、以及资源是否已复制
