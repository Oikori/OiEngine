# 音频

引擎音频系统基于 [miniaudio](https://github.com/mackron/miniaudio)（单头文件 + 一个 C 实现文件），封装在
`Engine/Engine/Audio/Audio.h`。对外只暴露 `AudioEngine` / `AudioClip` / `SoundInstance` 三个类型，
公开头文件不包含 miniaudio，避免把第三方结构体 / 宏带到业务代码和 DLL 客户端。

## 能力一览

- 2D 与 3D 声源；3D 支持听者位置 / 朝向、距离衰减（none / inverse / linear / exponential）、
  min / max distance 与 rolloff。
- 短音效整段预解码，同一 `AudioClip` 每次 `Play` 创建一个独立声部（voice），可以叠加播放。
- 长音频流式播放（`LoadClip(path, true)`），适合 BGM，不把整段 PCM 读进内存。
- 按规范化绝对路径缓存资源；同一路径重复 `LoadClip` 返回同一个 `AudioClip`。
- 主音量 / 静音、单声部音量 / 音高 / 循环 / 暂停 / 停止 / 跳转 / 播放位置查询。
- 引擎关闭时统一回收声部与资源；`Play` 的返回值可以丢弃，不需要手动管理一次性音效。

## 快速使用

```cpp
#include "OiEngine.h"

using namespace OiEngine;

// 加载（路径相对当前工作目录；也支持中文等 UTF-8 路径）
Ref<AudioClip> laser = AudioEngine::LoadClip("assets/audio/laser.wav");
if (!laser) {
    // 文件不存在 / 音频设备初始化失败时返回 nullptr，调用方无需抛异常
}

// 2D 一次性音效：返回值可以直接丢弃，AudioEngine::Update 会保留到播放结束
AudioPlaybackSettings shot;
shot.volume = 0.6f;
shot.pitch = 1.1f;
laser->Play(shot);

// 需要控制循环音乐时保留句柄
Ref<AudioClip> bgm = AudioEngine::LoadClip("assets/audio/bgm.mp3", /*streaming=*/true);
AudioPlaybackSettings music;
music.volume = 0.4f;
music.looping = true;
Ref<SoundInstance> musicVoice = bgm->Play(music);
musicVoice->SetVolume(0.3f);
musicVoice->Pause();
musicVoice->Resume();
musicVoice->Stop();
```

3D 声源：

```cpp
// 每帧跟随相机更新听者（位置单位与世界坐标一致即可，引擎不做单位换算）
AudioEngine::SetListenerPosition(cameraPosition);
AudioEngine::SetListenerDirection(cameraForward, cameraUp);

AudioPlaybackSettings emitter;
emitter.volume = 1.0f;
emitter.spatialized = true;
emitter.position = glm::vec3(4.0f, 0.0f, 0.0f);
emitter.attenuation = AudioAttenuation::Inverse;
emitter.minDistance = 1.0f;
emitter.maxDistance = 30.0f;
emitter.rolloff = 1.0f;
Ref<SoundInstance> voice = explosion->Play(emitter);

// 声源移动
voice->SetPosition(glm::vec3(6.0f, 1.0f, 0.0f));

// 关闭空间化后变成普通 2D 声部（音量不再随距离变化）
voice->SetSpatializationEnabled(false);
```

主音量与静音：

```cpp
AudioEngine::SetMasterVolume(0.8f);  // 0..1
AudioEngine::SetMuted(true);
AudioEngine::SetMuted(false);
```

## 生命周期

`Application` 已经自动管理音频子系统，业务层通常不需要调用这些函数：

| 时机 | 调用 |
|---|---|
| `Application::Init`（窗口创建后） | `AudioEngine::Init()` |
| 主循环每帧（窗口最小化时也执行） | `AudioEngine::Update()`，回收播放结束 / 暂停后丢弃的声部 |
| `Application::Shutdown`（层 Detach 之后、渲染器释放之前） | `AudioEngine::Shutdown()` |

如果绕过 `Application` 单独使用音频，需要自行按 `Init -> LoadClip/Play -> Update（每帧）-> Shutdown` 调用。

- 所有音频 API **只在主线程调用**。miniaudio 内部有自己的混音线程，但引擎没有对业务侧 API 做线程安全包装。
- `AudioEngine::Init` 失败（例如没有可用输出设备）只写 `OI_ERROR`，不会中断引擎启动；之后
  `IsInitialized()` 返回 false，`LoadClip` 返回 nullptr，`Play` 返回 nullptr。
- `Shutdown` 后，调用方仍然持有的 `AudioClip` / `SoundInstance` 会变成惰性对象：所有方法安全地空操作，
  再次 `Play` 返回 nullptr。可以重新 `Init`，旧句柄不会恢复。
- `Update` 只释放「引擎独占」的已结束声部；调用方仍持有句柄的声部会保留，方便再次 `Resume` / `SeekTo`。
  如果暂停后丢弃句柄，下一帧 `Update` 会回收它。

## 资源模型

```
AudioEngine (ma_engine + clip cache + active voices)
  ├── AudioClip "laser.wav"  (decode 模板 / 元数据)
  │     ├── SoundInstance 1  (ma_sound clone)
  │     └── SoundInstance 2
  └── AudioClip "bgm.mp3"    (stream 模板)
        └── SoundInstance    (独立解码流)
```

- `LoadClip` 用规范化后的绝对路径做缓存键；同一文件大小写不同 / 相对路径不同（在 Windows 语义下）
  会得到同一个 `AudioClip`。decode 与 stream 是两条独立缓存（键前缀不同）。
- **decode（默认）**：加载时完整解码成 PCM。每次 `Play` 通过 `ma_sound_init_copy` 克隆数据源，
  多个声部共享 PCM，只有游标和混音参数独立。适合爆炸、枪声、脚步等短音效，可以大量叠加。
- **stream（`LoadClip(path, true)`）**：不预解码。每次 `Play` 独立打开一条解码流，适合几 MB 以上的 BGM。
  流式声部的 `SeekTo` 会做 seek，但频繁 seek 有解码开销。
- 支持 miniaudio 内置解码器覆盖的格式（wav / mp3 / flac / ogg 等，取决于构建时启用的解码器）。
- 音频文件在加载时被完整读取；运行期间修改源文件不会热重载，需要重启或等后续资源热重载能力。

## 3D 听者与衰减

- 听者固定使用 index 0，`forward` / `up` 必须是世界空间方向；传零向量会被忽略并写 `OI_WARN`。
- 坐标右手系 / Y-up 与引擎渲染一致；引擎只透传数值，不强制单位。
- `AudioAttenuation::Inverse` 是默认值，等价于 OpenAL 的 `AL_INVERSE_DISTANCE_CLAMPED`。
- `minDistance` 内保持最大音量，`maxDistance` 外不再继续衰减；`rolloff` 控制衰减速度。
- 多次 `Play` 同一 `AudioClip` 得到的是独立声部，可以各自设置 3D 位置。

## miniaudio 集成方式

- 源码：`vendor/miniaudio/`（`miniaudio.h`、`miniaudio.c`、`LICENSE`），版本 0.11.25，直接入库，不是 submodule。
- `vendor/CMakeLists.txt` 把 `miniaudio.c` 编成静态库 `miniaudio`；根 `CMakeLists.txt` 显式
  `enable_language(C)`。Windows 额外链接 `ole32`、`winmm`。
- `Engine` 以 PRIVATE 方式链接 `miniaudio`，因此 `miniaudio.h` 不会出现在 Engine 的公共 include 路径中。
- Windows 下 miniaudio 的窄字符文件接口走 ANSI `fopen`；`AudioEngine::LoadClip` 会把路径规范化为
  `std::filesystem::path` 并调用 `ma_sound_init_from_file_w`，所以中文路径可用。
- 音频对象在 `Audio.cpp` 的 `Impl` 中持有 `ma_sound`，公开头文件只有 `Scope<Impl>` 前置声明。

## 示例：PlaneGame

飞机大战已经接入音效，可作为实际用法参考：

- 资源：`SandBox/assets/audio/` 下的 `laser.wav`、`explosion.wav`、`pickup.wav`、`hit.wav`。
  这些文件由 `SandBox/assets/audio/generate_audio.py` 程序化生成（44.1 kHz / 16-bit / mono），
  没有外部版权素材；重新生成用 `python SandBox/assets/audio/generate_audio.py`。
- 加载：`PlaneGameLayer::LoadSounds()`（`OnAttach` 时调用），使用相对当前工作目录的路径
  `assets/audio/laser.wav` 等。
- 播放：开火、导弹、击毁敌机、拾取补给、玩家受击处调用 `PlayOneShot`。
- 调试：游戏中按 F4 打开调试面板，可调主音量 / 静音，并点「测试音效」「测试爆炸」直接试听。
- 部署：`SandBox/CMakeLists.txt` 的 `POST_BUILD` 命令把 `SandBox/assets/` 复制到输出目录
  （`output/assets/`）。运行时以当前工作目录为资源根，因此需要在 `output/` 目录启动 SandBox，
  或把 `output/assets` 一并复制/部署到实际运行目录。

## 已知边界

- 没有音频总线 / SoundGroup（音乐、音效分组音量），目前只有全局主音量 + 单声部音量。
- 没有声部上限、优先级与抢占；同一帧大量 `Play` 会创建大量 `ma_sound`，由业务侧控制节奏。
- 没有淡入淡出、DSP 效果、播放结束回调、录音 / 麦克风采集；需要时可继续封装 miniaudio。
- 流式资源每个声部占一条解码流，不要对同一 BGM 每帧 `Play`。
- BGM 若需要单独停止，必须保留 `SoundInstance` 句柄；否则只能用 `AudioEngine::StopAll()` 全部停止。
- 音频不随窗口失焦 / 最小化自动暂停；若需要，在应用层监听事件调用 `Pause` / `Resume`。

## 验证

```powershell
# 日常构建（新增 Engine 源文件后需先重新配置，见 AGENTS.md）
cmake --preset mingw-debug
cmake --build build/cmake-build-debug
```

运行 `output/SandBox.exe` 时请把工作目录设为 `output/`（资源按当前工作目录读取），控制台应出现：

```text
[INFO] Audio: miniaudio 0.11.25 initialized (device '...', 48000 Hz, 2 ch)
[INFO] Audio: loaded '...\output\assets\audio\laser.wav' (0.18s, 48000 Hz, 1 ch, decode)
...
```

进入飞机大战后按 F4，用「测试音效 / 测试爆炸」验证输出；3D 声源可用
`AudioPlaybackSettings::spatialized = true` + `SetListenerPosition` / `SetListenerDirection` 观察距离衰减与声像。
